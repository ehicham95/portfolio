The Central Question

What We Want to Understand

When someone takes out a loan, they intend to pay it back. So what happens between the loan approval and default? What circumstances, characteristics, or decisions lead borrowers down the path of non-payment? This analysis uses machine learning to uncover the hidden patterns behind loan defaults.

Why This Matters

Understanding default behavior goes beyond just identifying risky borrowers. It helps us comprehend the human and financial factors that create payment difficulties. By revealing these patterns, we can better understand:

  • Financial Stress Indicators: What financial situations predict trouble ahead?
  • Borrower Characteristics: Which personal attributes correlate with default risk?
  • Loan Structure Impact: How do loan terms influence payment behavior?
  • Warning Signs: What early indicators suggest potential default?

Root Cause Analysis

The key findings from our machine learning analysis can be traced back to clear real-world financial behaviors and circumstances:

  • Why do poor credit grades (D/E) predict defaults so strongly? These grades reflect past financial struggles and payment difficulties. Borrowers with these grades have already demonstrated challenges managing debt obligations, making future defaults more likely.
  • Why does high debt-to-income ratio (>25%) drive defaults? When debt payments consume more than a quarter of income, borrowers have little financial cushion for unexpected expenses or income disruptions, leading to payment failures.
  • Why are renters 35% more likely to default? Renting often indicates lower net worth and financial stability compared to homeownership. Renters may face housing instability that can disrupt their ability to maintain consistent loan payments.
  • Why does employment instability (0-5 years) increase default risk? Job uncertainty directly impacts income reliability. Borrowers with unstable employment history are more vulnerable to income shocks that can trigger defaults.

Technical Challenges Overcome

  • Class Imbalance - The Low Recall Problem
    Challenge: Only small percentage of borrowers default, creating severe class imbalance that makes ML models conservative.

    Why This Causes Low Recall:
    • Models predict "no default" for most cases to achieve high accuracy
    • Limited default examples make it hard to learn nuanced warning signs
    • Results in missing many actual defaulters (low recall)

    Solution: Used F-beta scoring (β=1.5), SMOTE (Synthetic Minority Oversampling Technique) to generate synthetic default examples, cost-sensitive learning with strategic class weights, and ensemble methods to achieve 73% recall while maintaining 92.85% precision.
  • Confusing Features That Mislead Machine Learning
    Challenge: Several features actually confused ML models rather than helping identify default patterns.

    Examples of Confusing Features:
    • High-income borrowers defaulting at unexpected rates
    • Employment length containing misleading signals (job hoppers vs. career changers)
    • Age-income interactions breaking simple assumptions
    • Loan purpose ambiguity (debt consolidation: responsible vs. desperate)

    Solution: Used SHAP analysis to identify confusing features and engineered composite features that better captured true behavioral patterns.
  • Missing Value Imputation Strategy Selection
    Challenge: 895 missing values in employment_length (2.7% of data) required careful handling to avoid introducing bias.

    Statistical Approach:
    • Compared 4 imputation methods: mean, median, mode, and IterativeImputer
    • Used cross-validation to measure impact on model performance
    • IterativeImputer showed best preservation of data relationships
    • Validated that imputed values maintained realistic employment duration distributions

    Solution: Selected IterativeImputer based on statistical performance metrics, ensuring imputed values didn't create artificial patterns in the data.
  • Outlier Detection and Data Quality
    Challenge: Extreme values could skew ML model learning and create misleading patterns.

    Logical Approach:
    • Applied domain knowledge to identify unrealistic values (income >$500K, impossible loan terms)
    • Used statistical thresholds combined with business logic
    • Focused on values that violated fundamental lending principles
    • Preserved legitimate high-value cases while removing data entry errors

    Solution: Removed extreme outliers using logical constraints rather than purely statistical methods, ensuring cleaned data reflected realistic borrower profiles.
